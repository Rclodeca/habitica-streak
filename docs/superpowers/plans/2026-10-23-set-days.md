# Set-day Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a daily habit rest on chosen days of the week. It hits like a daily on its due days, does nothing on rest days, and draws from the daily pool as a fraction of a habit.

**Architecture:** A set-day habit stays `period: 'daily'` with a new optional `days` list (Mon = 0 … Sun = 6). Engine helpers in `habits.ts`/`time.ts` decide "due today" and the fractional pool weight. Store/actions/rollover guard rest days. The UI adds a Resting fold to the skills list, a shared `DayPicker` used by Forge and the skill popup, and lifts the skill popup into `HabitList` so it survives a row moving into or out of the fold.

**Tech Stack:** Vue 3 (`<script setup>`), TypeScript, Pinia, Vitest + @vue/test-utils (jsdom), SCSS theme overrides.

**Spec:** `docs/superpowers/specs/2026-10-23-set-days-design.md` (mockup `docs/mockups/set-days.html`: List C, Forge B, Skill popup C)

## Global Constraints

- Weekday index: **Mon = 0 … Sun = 6**, taken from the Pacific business day (3am-to-3am, `pacificBusinessDay` in `time.ts`).
- `Habit.days`: sorted, unique, length 1–6, only on `period === 'daily'`. Seven days (or none) = plain daily = **key absent**. No `CURRENT_SCHEMA_VERSION` bump, no migration.
- Per hit: `d_i = pool * w_i / max(W, w_i)` with `W = Σ w_j * f_j`, `f = days.length / 7` (1 for plain dailies and all weeklies), `pool = S * poolSizeMultiplier(W)`.
- Overdrive works on set-day habits exactly as on dailies; on a rest day neither the habit nor its Overdrive can be used.
- Player-facing copy is terse: only "Resting", "Days", "Every day", "N days", "1 day", and short day names (Mon…Sun) / letters (M T W T F S S). No explanatory sentences.
- Tap targets ≥ 44px (day buttons 44px tall, Resting toggle row ≥ 44px).
- Components read time through `useDebugClockStore().now()`, never `new Date()`.
- No `localStorage` from components; persistence stays behind the stores. No new dependencies.
- Base scoped styles = the Minimalist look; Ashen overrides go in `src/assets/scss/themes/ashen.scss` (diamond days, dashed hollow diamond, Cinzel caps), matching the mockup.
- Commit messages follow the repo's plain-sentence style and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Test command: `npx vitest run <path>`; full suite `npm run test:unit`; type check `npx vue-tsc -b`.

## Review Focus

- **The 3am boundary.** At 2:59am Pacific on a Tuesday it is still Monday, so a Mon-only habit is still due → Task 1 `isDueOn` boundary test.
- **Taking today out of a habit after checking it off.** The row moves to Resting and stays checked, the check is disabled, and Overdrive is refused in the engine and the popup → Task 3 `activateOverdrive` test, Task 7 popup test.
- **The debug "Skip to next day" clock.** Resting state follows `debugClockStore.now()` → Task 5 debug-clock test.
- **The skill popup open while its row changes lists.** Tapping today's day in the popup must not close it when the row moves into or out of the fold → Task 7 regression test (mounted through `HabitList`).
- **Old saves and odd data.** A habit with no `days`, or a weekly that somehow has `days`, behaves exactly as today → Task 1 weekly/undefined tests.

**Interfaces:**
- Produces:
  - `dayOfWeekIndex(date: Date): number`: Mon = 0 … Sun = 6, from `pacificBusinessDay(date)`.
  - `Habit.days?: number[]`: optional field with a comment in the style of the other optional `Habit` fields.
  - `normalizeDays(days: number[] | undefined): number[] | undefined`: sorted, deduped, only integers 0–6. Returns `undefined` for undefined, empty, or all seven.
  - `dueFraction(habit: Habit): number`: `days.length / 7` for a daily with `days`, else `1`.
  - `isDueOn(habit: Habit, date: Date): boolean`: `true` for weeklies and for dailies without `days`, else `days.includes(dayOfWeekIndex(date))`.
  - `nextDueDay(days: number[], today: number): number`: the first weekday after `today`, wrapping, that is in `days`.
  - `createHabit(name, period, difficulty, isBad, rng, days?: number[]): Habit`: sets `days` to `normalizeDays(days)` only when `period === 'daily'`, and omits the key when that's `undefined`.
